# MCP Proxy Conformance

Target MCP spec: `2025-11-25`.

The local conformance matrix is generated by:

```bash
uv run velvet mcp conformance --json
```

## Method Matrix

| Method | Behavior | Notes |
|---|---|---|
| `initialize` | Lifecycle-forwarded | IDs are preserved; upstream server info and capabilities are passed through. |
| `notifications/initialized` | Lifecycle-forwarded | Notification is forwarded without a proxy response. |
| `ping` | Lifecycle-forwarded | Transparent unless upstream fails. |
| `tools/list` | Enforced | Inventory is classified and filtered; only approved non-drifted tools are exposed. |
| `tools/call` | Enforced | Pre-execution OAP Decision, Velvet-signed Max-DE Certificate Envelope, Ledger persistence, and forwarding proof. |
| `resources/*` | Bounded-governed | Strict default block; recorded passthrough requires explicit config. |
| `prompts/*` | Bounded-governed | Strict default block; recorded passthrough requires explicit config. |
| `tasks/*` | Bounded-governed | Strict default block. |
| Non-lifecycle notifications | Bounded-governed | Strict default block; notification response rules are preserved. |
| Unknown methods | Bounded-governed | Strict default block; no silent upstream propagation. |

## Transport Matrix

| Transport | Status | Notes |
|---|---|---|
| stdio | Supported | Newline-delimited JSON-RPC, subprocess stdio isolation, bounded request handling. |
| Streamable HTTP | Supported | MCP `2025-11-25` POST JSON/SSE responses, GET SSE listen streams, sessions, DELETE termination, bounded Last-Event-ID replay, request limits, Origin checks, and optional bearer auth. |
| Legacy SSE | Unsupported by default | Not added as a production path. |

## JSON-RPC Behavior

- Requests, responses, notifications, and errors are parsed as JSON-RPC 2.0.
- Parse errors return `-32700`.
- Invalid requests return `-32600`.
- Policy denials use Velvet policy-domain errors, not upstream errors.
- Upstream errors are preserved only for lifecycle-forwarded and explicitly
  allowed passthrough paths.
- Batch requests are supported for stdio/backwards-compatible runtime paths; MCP
  `2025-11-25` Streamable HTTP rejects batch POST bodies.
- Notification tool calls and bounded notifications are still governed and do
  not produce proxy responses.

## Streamable HTTP Capabilities

| Capability | Status | Notes |
|---|---|---|
| Sessions | Supported | Captures upstream `MCP-Session-Id` on `initialize`, validates visible ASCII IDs, and requires known sessions for stateful follow-up requests. |
| GET SSE | Supported | Requires `Accept: text/event-stream`; each downstream stream uses an independent upstream listen stream. |
| POST SSE responses | Supported | Upstream `text/event-stream` responses are parsed and re-emitted with proxy event IDs. |
| Last-Event-ID replay | Supported | Bounded in-memory replay is scoped to the matching session stream only. |
| DELETE session termination | Supported | Forwards upstream DELETE when stateful and removes local session/replay state. |
| JSON-RPC response forwarding | Supported | Client responses are forwarded upstream and return HTTP `202` after acceptance. |
| Origin/auth checks | Supported | Origin allow-list and optional bearer auth run before upstream forwarding. |

## Known Limitations

- `resources/*` and `prompts/*` are bounded-governed but do not receive
  semantic content enforcement in this scoped gateway.
- JSON Schema argument validation covers the subset used by MCP tool inputs.
- OpenTelemetry export is documented as an integration path, not enabled by
  default in the crate.
